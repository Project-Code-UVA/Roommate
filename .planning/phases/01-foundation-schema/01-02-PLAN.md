  <action>
    Create SQL migration files in `supabase/migrations/` directory. Each migration is one logical unit. Follow the exact schema from RESEARCH.md Code Examples section, which is the PRD v2.0 reconciled schema.

    **Migration order (CRITICAL — foreign key dependencies, see RESEARCH.md Pitfall 3):**

    1. `00001_create_enums.sql` — All enum types:
       - mode_status (roommate, friends, found_roommate)
       - enforcement_state (none, warning, dm_ban_48h, suspended_7d, permanent_ban)
       - thread_status (active, unmatched, blocked)
       - report_reason (harassment, sexual_content, hate_speech, spam, impersonation, underage, safety_threat, other)
       - report_status (pending, reviewed, resolved, dismissed)
       - enforcement_action_type (warning, dm_ban_48h, suspended_7d, permanent_ban)
       - moderation_status (pending, approved, rejected)

    2. `00002_create_users.sql` — Users table (references auth.users)
    3. `00003_create_schools.sql` — Schools table (independent)
    4. `00004_create_user_schools.sql` — User-Schools junction (FK to users + schools). Include index on school_id.
    5. `00005_create_profiles.sql` — Profiles (FK to users). Include `nitty_gritty jsonb DEFAULT '{}'::jsonb` for roommate preferences.
    6. `00006_create_photos.sql` — Photos (FK to users). Include moderation_status and order_index. Index on user_id.
    7. `00007_create_likes.sql` — Likes (FK to users x2). UNIQUE(liker_id, liked_id). Index on liked_id.
    8. `00008_create_matches.sql` — Matches (FK to users x2). UNIQUE(user_a_id, user_b_id). CHECK(user_a_id < user_b_id) for canonical ordering. Index on user_b_id.
    9. `00009_create_dismissals.sql` — Dismissals (FK to users x2). UNIQUE(dismisser_id, dismissed_id).
    10. `00010_create_saves.sql` — Saves/bookmarks (FK to users x2). UNIQUE(saver_id, saved_id).
    11. `00011_create_threads.sql` — Threads (FK to users x2, FK to matches). Status uses thread_status enum. NO routing_state_for_recipient (removed per PRD v2.0). CHECK(user_a_id < user_b_id). UNIQUE(user_a_id, user_b_id).
    12. `00012_create_messages.sql` — Messages (FK to threads, FK to users). Indexes on thread_id and (thread_id, created_at).
    13. `00013_create_blocks.sql` — Blocks (FK to users x2). Composite PK (blocker_id, blocked_id). Index on blocked_id.
    14. `00014_create_reports.sql` — Reports (FK to users x2). Uses report_reason and report_status enums.
    15. `00015_create_enforcement_actions.sql` — Enforcement actions (FK to users). Uses enforcement_action_type enum. Index on user_id.
    16. `00016_create_ranking_config.sql` — Ranking config (independent). weight_name UNIQUE, weight_value numeric(5,4).
    17. `00017_create_ads_engagement.sql` — Ads engagement tracking (FK to users).
    18. `00018_create_subscriptions.sql` — Subscriptions (FK to users).

    **Apply migrations** using Supabase MCP `apply_migration` tool for each file, in order. If MCP unavailable, write the files locally and instruct user to apply via Supabase dashboard SQL editor.

    - Insert initial ranking_config weights: completeness=0.3000, activity=0.2500, verification=0.2000, engagement=0.1500, freshness=0.1000

    Apply seed data after migrations.

    - Add thread_status enum
    - Note that migrations are the source of truth
