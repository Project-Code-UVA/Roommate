**src/services/enforcement-service.ts** -- New service for checking enforcement state:
- Import `supabase` from `@/lib/supabase` and types from `@/types/safety`
- `getEnforcementInfo(userId: string): Promise<EnforcementInfo>` -- queries `users` table for `enforcement_state`, then queries `enforcement_actions` for the most recent action matching that state (ordered by `created_at DESC LIMIT 1`). Returns `{ state, endAt: action?.end_at ?? null, action }`.
- `isActionBlocked(action: "like" | "message" | "swipe" | "explore", state: EnforcementState): boolean` -- pure function (no async). Logic:
  - `"none"` or `"warning"`: NEVER blocked for any action
  - `"dm_ban_48h"`: blocks `"message"` only; allows `"like"`, `"swipe"`, `"explore"`
  - `"suspended_7d"` or `"permanent_ban"`: blocks ALL actions
- `getActiveEnforcement(userId: string): Promise<EnforcementAction | null>` -- queries `enforcement_actions WHERE user_id = userId ORDER BY created_at DESC LIMIT 1`.
- All functions return structured data (never throw).

**src/services/block-service.ts** -- Extend with `blockUser`:
- Keep existing `blockFromChat` function unchanged
- Add `blockUser(userId: string, otherUserId: string): Promise<BlockResult>` that calls `supabase.rpc('block_user', { p_blocker_id: userId, p_blocked_id: otherUserId })` using the same `supabase.rpc.bind(supabase) as any` cast pattern from match-service.
- Parse RPC response: if `data.error`, return `{ success: false, error: data.error }`. If `data.success`, return `{ success: true, error: null }`.
- Import `BlockResult` type from `@/types/safety`.

**src/services/selfie-service.ts** -- New service for selfie verification:
- Import `ImagePicker` from `expo-image-picker`, `FileSystem` from `expo-file-system`, `decode` from `base64-arraybuffer`, `supabase` from `@/lib/supabase`, `SelfieResult` from `@/types/safety`
- `captureSelfie(): Promise<ImagePicker.ImagePickerResult>` -- calls `ImagePicker.launchCameraAsync({ cameraType: ImagePicker.CameraType.front, allowsEditing: true, aspect: [1, 1], quality: 0.8, mediaTypes: ["images"] })` per D-01
- `uploadSelfie(userId: string, uri: string): Promise<SelfieResult>` -- follows photo-service base64 upload pattern:
  1. `FileSystem.readAsStringAsync(uri, { encoding: FileSystem.EncodingType.Base64 })`
  2. `supabase.storage.from("selfies").upload(\`${userId}/selfie.jpg\`, decode(base64), { contentType: "image/jpeg", upsert: true })` -- `upsert: true` per D-04
  3. On upload success, call `supabase.rpc('set_selfie_verified', { p_user_id: userId })` using same RPC cast pattern
  4. Get public URL via `supabase.storage.from("selfies").getPublicUrl(\`${userId}/selfie.jpg\`)`
  5. Return `{ url: publicUrl, error: null }` on success or `{ url: "", error: errorMessage }` on failure
  6. Wrap in try/catch returning `{ url: "", error: message }` like photo-service pattern

**src/hooks/use-enforcement.ts** -- Hook for enforcement state on app lifecycle:
- `useEnforcement(userId: string | undefined)` returns `{ enforcementInfo: EnforcementInfo | null, isLoading: boolean, showWarningModal: boolean, dismissWarning: () => void }`
- On mount (when userId changes), call `getEnforcementInfo(userId)`
- If state is `"warning"`, set `showWarningModal = true` (per D-07: shown on next app open)
- `dismissWarning()` sets `showWarningModal = false` and could optionally clear the warning state via RPC (but for v1, just dismiss the modal client-side)
- If state is `"permanent_ban"`, the hook signals this but the ban screen is handled at the layout level (Plan 03)
