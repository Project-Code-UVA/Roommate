## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, overflow menu separator inset |
| sm | 8px | Compact element spacing, row padding, back-button pad |
| md | 16px | Default element spacing, card padding, section insets |
| lg | 24px | Section padding, modal content margins |
| xl | 32px | Layout gaps, selfie capture frame margin |
| 2xl | 48px | Major section breaks, enforcement modal top spacing |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions: Touch targets for overflow menu button use 44px minimum (iOS HIG) even though 44 is not on the scale. Achieved via 4px padding around 36px hit area.

## Typography

| Role | Size | Weight | Line Height | Usage in Phase 7 |
|------|------|--------|-------------|-------------------|
| Body | 16px | 400 | 1.5 (24px) | Report description, enforcement modal body, verification instructions |
| Label | 14px | 700 | 1.4 (20px) | Report category labels, settings row labels, badge captions |
| Heading | 20px | 700 | 1.2 (24px) | Modal titles ("Warning", "Account Suspended", "Verify Your Identity") |
| Display | 28px | 700 | 1.2 (34px) | Permanent ban message on login screen only |

Source: Matches existing codebase -- body 16px (chat-header displayName), label 14px (settings editText), heading 20px (section headers), display 28px (photo-carousel nameText). Weight consolidated to 2 values: 400 (body) and 700 (label, heading, display).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) / `#f5f5f5` (light gray) | Backgrounds, modal surfaces, settings rows |
| Secondary (30%) | `#f3f4f6` (gray-100) / `#111827` (gray-900 for dark surfaces) | Report category selection cards, enforcement modal header, overflow dropdown |
| Accent (10%) | `#7c3aed` (primary-600) | Verified badge CTA button, selfie capture button, verification banner CTA |
| Destructive | `#ef4444` (red-500) | Block label, permanent ban text, report submit button, destructive confirmations |
| Warning | `#f59e0b` (amber-500) | Warning enforcement modal icon, DM ban status indicator |
| Success | `#4ade80` (green-400) | Selfie verified confirmation checkmark, verified badge icon overlay |

Accent reserved for:
- "Verify Now" CTA button in post-onboarding banner
- "Verify Identity" CTA in profile settings
- Selfie capture shutter button ring
- Verified badge checkmark icon (`Ionicons checkmark-circle` at `primary-400` / `#a78bfa` -- established pattern)

Destructive reserved for:
- "Block" menu label text
- "Report" submit button (when category selected)
- Permanent ban screen headline
- Delete/block confirmation dialog destructive action button

## Interaction Contracts

### Overflow Menu (Block/Report)

| Step | Interaction | Visual Feedback |
|------|------------|-----------------|
| 1 | User taps 3-dot icon (`ellipsis-horizontal`, 22px, `#111827`) | Menu icon press state (opacity 0.7) |
| 2 | Dropdown appears | White card (`#fff`), 12px border-radius, shadow (0,4 offset, 0.15 opacity, 12px blur), 140px min-width, positioned top-right |
| 3 | Invisible full-screen backdrop renders behind dropdown | Transparent pressable covers entire screen |
| 4a | User taps "Block" | Red text (`#ef4444`) + `ban-outline` icon. Triggers block-confirm-dialog. |
| 4b | User taps "Report" | Gray text (`#374151`) + `flag-outline` icon. Opens report-sheet. |
| 4c | User taps backdrop | Menu closes, no action |

### Block Flow

| Step | Interaction | Visual Feedback |
|------|------------|-----------------|
| 1 | User taps "Block" from overflow | Alert.alert appears: "Block [name]?" |
| 2 | Alert body | "They won't be able to see your profile or message you. You won't see them anywhere in the app." |
| 3a | User taps "Block" (destructive) | Profile modal/sheet dismisses immediately. Profile removed from current feed optimistically. Toast: "Blocked." |
| 3b | User taps "Cancel" | Alert dismisses, no action |

### Report Flow

| Step | Interaction | Visual Feedback |
|------|------------|-----------------|
| 1 | User taps "Report" from overflow | Bottom sheet slides up with 8 report categories |
| 2 | Sheet header | "Report [name]" in heading style (20px, weight 700) |
| 3 | Category list | 8 pressable rows, each with icon + label. Single-select highlight: selected row gets `primary-50` (`#f5f3ff`) background + `primary-600` left border (3px) |
| 4 | User selects category | Description textarea appears below categories (placeholder: "Add details (optional)"). Submit button enables. |
| 5a | User taps "Submit Report" | Button shows loading spinner. On success: sheet dismisses, toast: "Report submitted. Thank you." |
| 5b | User taps "Submit Report" (error) | Button re-enables. Error text appears below: "Something went wrong. Please try again." |
| 6 | User swipes sheet down | Sheet dismisses, no report submitted |

Report categories with icons:

| Category | Display Label | Icon |
|----------|--------------|------|
| harassment | Harassment | `hand-left-outline` |
| sexual_content | Sexual Content | `eye-off-outline` |
| hate_speech | Hate Speech | `megaphone-outline` |
| spam | Spam | `mail-unread-outline` |
| impersonation | Impersonation | `people-outline` |
| underage | Underage User | `alert-circle-outline` |
| safety_threat | Safety Threat | `warning-outline` |
| other | Other | `ellipsis-horizontal-circle-outline` |

### Selfie Verification Flow

Primary focal point: the oval face guide frame is the visual anchor; the shutter button is the primary action target.

| Step | Interaction | Visual Feedback |
|------|------------|-----------------|
| 1a | Post-onboarding: banner appears at top of Discovery | Light purple banner (`primary-50` bg). Shield icon + "Verify your identity" + "Verify Now" CTA button (primary-600 bg, white text) + dismiss X |
| 1b | From settings: user taps "Verify Identity" row | Navigation to selfie capture screen |
| 2 | Camera screen opens | Full-screen camera preview. Oval face guide overlay (white stroke, 2px, 60% opacity). Instructions text below oval: "Position your face within the frame" |
| 3 | Shutter button at bottom center | Circular button: 72px outer (primary-600 border, 3px), 56px inner (white fill). Press state: scale to 0.9 + opacity 0.8 |
| 4 | User taps shutter | Camera captures. Brief flash overlay (white, 200ms fade). Preview replaces live camera. |
| 5 | Preview with two buttons | "Retake" (outline style, gray-700 text) and "Use Photo" (filled primary-600, white text) |
| 6a | User taps "Use Photo" | Loading spinner on button. Upload to Supabase Storage. On success: navigate back, toast: "Selfie verified!" Badge appears on profile. |
| 6b | User taps "Retake" | Camera preview resumes, no upload |
| 7 | Error during upload | Button re-enables. Error text: "Upload failed. Please try again." |

### Enforcement State Modals

| Property | Value |
|----------|-------|
| Trigger | Next app open after warning enforcement action |

## State Matrix

| State | Visual Treatment | Trigger |
|-------|-----------------|---------|
| Selfie unverified | No badge anywhere. Settings row shows "Not verified" in gray-400 + "Verify Identity" chevron. | Default for new users |
| Selfie verified | Checkmark-circle badge on all profile surfaces. Settings row shows "Verified" in green-500 + "Re-upload" chevron. | After successful selfie upload |
| Warning active | Warning modal on next app open. No other UI restrictions. | enforcement_actions record with type=warning |
| DM ban active | Read-only messaging. Send button disabled (opacity 0.4). Tapping shows DM ban modal. Swipe/browse still works. | enforcement_state=dm_ban on user |
| Suspended | Full app read-only. All action buttons disabled (opacity 0.4). Suspension modal on app open. | enforcement_state=suspended on user |
| Permanently banned | Ban screen replaces entire app. Only sign-out available. | enforcement_state=banned on user |
| Report in progress | Submit button shows ActivityIndicator. Category selection and textarea disabled during submission. | submitReport() in flight |
| Block in progress | Alert dismissed. Optimistic removal of profile from feed. Rollback + error toast if server fails. | blockUser() in flight |
