Create 4 SQL migration files. Apply each via Supabase MCP (same pattern as Phases 1-3).

**00035_message_reply_to.sql:**
- ALTER TABLE public.messages ADD COLUMN reply_to_id uuid REFERENCES public.messages(id) ON DELETE SET NULL
- CREATE INDEX idx_messages_reply_to ON public.messages(reply_to_id) WHERE reply_to_id IS NOT NULL

**00036_message_reactions.sql:**
- CREATE TABLE public.message_reactions with columns: id (uuid PK default gen_random_uuid()), message_id (uuid NOT NULL FK messages ON DELETE CASCADE), user_id (uuid NOT NULL FK users ON DELETE CASCADE), emoji (text NOT NULL), created_at (timestamptz NOT NULL DEFAULT now())
- UNIQUE constraint on (message_id, user_id, emoji)
- CREATE INDEX idx_reactions_message_id ON public.message_reactions(message_id)
- Enable RLS
- Policy "reactions_select_thread_participant": SELECT for authenticated, USING EXISTS check that user is thread participant via messages->threads join
- Policy "reactions_insert_own": INSERT for authenticated, WITH CHECK user_id = auth.uid() AND user is thread participant
- Policy "reactions_delete_own": DELETE for authenticated, USING user_id = auth.uid()

**00037_send_message_rpc.sql:**
- CREATE OR REPLACE FUNCTION public.send_message(p_thread_id uuid, p_sender_id uuid, p_body text DEFAULT NULL, p_media_url text DEFAULT NULL, p_reply_to_id uuid DEFAULT NULL, p_message_id uuid DEFAULT NULL) RETURNS jsonb
- LANGUAGE plpgsql SECURITY DEFINER SET search_path = public
- Logic: Validate thread exists and is active, validate sender is participant (user_a_id or user_b_id), determine other_id, check is_blocked(sender, other), check shares_school(sender, other), check enforcement_state != 'none' on sender, require body or media_url not both null, INSERT into messages with COALESCE(p_message_id, gen_random_uuid()) for optimistic ID pattern, return jsonb with success + message_id
- Return error codes: thread_not_found, thread_not_active, not_participant, blocked, no_shared_school, under_enforcement, empty_message

**00038_realtime_publication.sql:**
- ALTER PUBLICATION supabase_realtime ADD TABLE messages
- ALTER PUBLICATION supabase_realtime ADD TABLE message_reactions

Apply all 4 migrations via Supabase MCP in sequence (00035 -> 00036 -> 00037 -> 00038).
