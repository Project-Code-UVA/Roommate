1. Create `src/types/explore.ts` with three readonly types:

- `ExploreProfile`: Minimal grid data — `user_id: string`, `display_name: string`, `year: string | null`, `photo_url: string`, `selfie_verified: boolean`. This is what the grid RPC returns.
- `LikedMeProfile`: For liked-me grid — `user_id: string`, `photo_url: string`, `display_name: string | null` (null for free users, server omits), `liked_at: string`.
- `MyLike`: For my-likes grid — `user_id: string`, `display_name: string`, `year: string | null`, `photo_url: string`, `liked_at: string`.

All types must be `readonly` per project convention.

2. Create `supabase/migrations/00039_get_explore_feed.sql`:
- `get_explore_feed(p_user_id uuid, p_limit int DEFAULT 24, p_offset int DEFAULT 0, p_seed int DEFAULT 0)` returns jsonb.
- CTE structure: candidates -> scored -> ranked (mirroring get_discovery_stack pattern).
- Candidates: All users where `onboarding_completed = true`, `enforcement_state = 'none'`, `mode_status IN ('roommate', 'friends')`, NOT blocked (`NOT is_blocked(p_user_id, p.user_id)`), NOT dismissed (LEFT JOIN dismissals WHERE dismisser_id = p_user_id), NOT self.
- NOTE: Shows profiles from ANY school (not just shared schools) per user decision. Do NOT add shared-school filter.
- Scoring: Use `setseed(p_seed / 2147483647.0)` for deterministic random. Score = 0.7 * normalized_engagement + 0.3 * random(). Engagement = likes received in last 30 days, normalized by average across all users (capped at 1.0).
- Read explore-specific weights from `ranking_config` table (weight_name LIKE 'explore_%'). Fall back to hardcoded defaults if not found.
- Return: jsonb array of `{user_id, display_name, year, photo_url, selfie_verified}`. photo_url = first approved photo by order_index.
- SECURITY DEFINER, search_path = public.

3. Create `supabase/migrations/00040_get_my_likes.sql`:
- `get_my_likes(p_user_id uuid, p_limit int DEFAULT 24, p_offset int DEFAULT 0)` returns jsonb.
- Returns profiles the user has liked where NO reciprocal like exists (pending likes only).
- Join likes table (liker_id = p_user_id) with NOT EXISTS (SELECT 1 FROM likes WHERE liker_id = liked_id AND liked_id = p_user_id).
- Also exclude where a match already exists.
- Return: jsonb array of `{user_id, display_name, year, photo_url, liked_at}`.

4. Create `supabase/migrations/00041_get_liked_me.sql`:
- `get_liked_me(p_user_id uuid, p_limit int DEFAULT 24, p_offset int DEFAULT 0, p_is_paid boolean DEFAULT false)` returns jsonb.
- Returns profiles that have liked the current user where no reciprocal like/match exists yet.
- CRITICAL: When `p_is_paid = false`, return ONLY `{user_id, photo_url, liked_at}` — NO display_name or other identifying info. This prevents data leaks.
- When `p_is_paid = true`, return full `{user_id, display_name, photo_url, liked_at}`.
- Count function variant: Also create `get_liked_me_count(p_user_id uuid)` returns integer for badge.

5. Create `supabase/migrations/00042_seed_explore_weights.sql`:
- INSERT into `ranking_config` explore-specific weights: `explore_engagement` (0.35), `explore_activity` (0.25), `explore_completeness` (0.20), `explore_verification` (0.10), `explore_freshness` (0.10).
- Use ON CONFLICT DO NOTHING so re-running is safe.

Apply all 4 migrations via Supabase MCP (same pattern as prior phases).
