```sql
  p_user_id uuid,
  p_limit integer DEFAULT 20,
  p_offset integer DEFAULT 0
)

LANGUAGE plpgsql
SECURITY DEFINER

```

The function must:
1. Get the requesting user's school IDs (array_agg from user_schools)
2. Get the requesting user's dealbreakers from profiles.nitty_gritty->'dealbreakers'
3. Get the requesting user's preferences from profiles.nitty_gritty->'preferences'
4. Read ranking weights from ranking_config table (discovery_compatibility, discovery_activity, discovery_popularity)
5. Query profiles joined with users and user_schools with these WHERE clauses:
   - `us.school_id = ANY(v_user_schools)` (shared school gating - DISC-05)
   - `p.user_id != p_user_id` (not self)
   - `u.mode_status IN ('roommate', 'friends')` (exclude found_roommate - DISC-09)
   - `u.onboarding_completed = true`
   - `u.enforcement_state = 'none'`
   - `NOT is_blocked(p_user_id, p.user_id)`
   - Dismissal logic: LEFT JOIN dismissals, exclude where `view_count >= 3` OR `last_dismissed_at > now() - interval '48 hours'` (48-hour refresh, max 2 re-entries per user decision)
   - Dealbreaker filtering: for each category in the requesting user's dealbreakers, exclude candidates whose `nitty_gritty->'self'->>category` matches any value in the dealbreaker array (DISC-07)
6. Calculate three scoring components normalized to 0-1:
   - **Compatibility** (40% weight): Count how many of the requesting user's preferences match the candidate's self-values. Score = matching_categories / overlapping_categories. If no overlap, score = 0.5 (neutral).
   - **Activity** (35% weight): `1.0 - LEAST(EXTRACT(EPOCH FROM (now() - u.last_active_at)) / (7 * 86400), 1.0)` (decays linearly over 7 days to 0)
   - **Popularity** (25% weight): Count of likes received in last 30 days, normalized. Use `LEAST(like_count::float / GREATEST(avg_likes, 1), 1.0)` where avg_likes is computed from the school's population.
7. Rank by `(compatibility * w_compat + activity * w_activity + popularity * w_popularity) DESC`
8. Use `DISTINCT ON (p.user_id)` or `GROUP BY` to deduplicate multi-school overlaps
9. Apply LIMIT and OFFSET for pagination
10. Return COALESCE(result, '[]'::jsonb) for empty state (DISC-10)
11. Include mode_status in the result so the client can show "Looking for friends" badge

For the dealbreaker NOT EXISTS subquery, iterate over the requesting user's dealbreaker keys and check if candidate's self-value for that key appears in the dealbreaker array. Use jsonb_each_text for iteration and jsonb_array_elements_text for array comparison.

For the popularity subquery, use a lateral join or subquery: `SELECT COUNT(*) FROM likes WHERE liked_id = p.user_id AND created_at > now() - interval '30 days'`.

The function `public.like_profile(p_liker_id uuid, p_liked_id uuid) RETURNS jsonb` must:
1. Validate not blocked via is_blocked()
2. Validate shares_school() returns true
3. Check enforcement_state != 'none' on the liker

6. Check for reciprocal like (SELECT 1 FROM likes WHERE liker_id = p_liked_id AND liked_id = p_liker_id)
7. If mutual: INSERT INTO matches (user_a_id = LEAST, user_b_id = GREATEST) RETURNING id, then INSERT INTO threads (user_a_id, user_b_id, match_id) RETURNING id
8. Return jsonb: { success: true, is_match: bool, match_id: uuid|null, thread_id: uuid|null } on success, or { error: string } on validation failure

CRITICAL: Use LEAST(p_liker_id, p_liked_id) and GREATEST(p_liker_id, p_liked_id) for user_a_id/user_b_id to satisfy the CHECK constraint on matches and threads.

Create `supabase/migrations/00032_unmatch_user.sql`:

The function `public.unmatch_user(p_user_id uuid, p_other_id uuid, p_block_too boolean DEFAULT false) RETURNS jsonb` must:
1. Compute canonical ordering: v_user_a = LEAST, v_user_b = GREATEST
2. UPDATE matches SET unmatched_at = now(), unmatched_by = p_user_id WHERE user_a_id = v_user_a AND user_b_id = v_user_b AND unmatched_at IS NULL
3. UPDATE threads SET status = 'unmatched' WHERE user_a_id = v_user_a AND user_b_id = v_user_b
4. If p_block_too: INSERT INTO blocks ON CONFLICT DO NOTHING, and INSERT INTO dismissals (view_count = 3) ON CONFLICT DO UPDATE SET view_count = 3 (permanent dismissal)
5. DELETE likes in both directions
6. Return { success: true }
